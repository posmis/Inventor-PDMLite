# Сбор файлов по списку

Отдельная утилита (не часть PdmLite и не плагин Inventor): находит файлы Inventor по списку имён
в папке с компонентами и копирует их в одну папку — вместе с зависимостями сборок.

## Быстро

1. В Inventor: «Диагностика сборки» → «Ненайденные файлы» → **«Копировать имена»**.
2. Двойной щелчок по **`Collect-Components.cmd`**.
3. Выберите папку с компонентами (где искать) и папку, куда собрать.
4. В папке результата — файлы и `_отчёт.txt`: что найдено и откуда, что не найдено, где нашлось
   несколько файлов с одним именем.

## Из PowerShell

```powershell
# список из буфера обмена
.\Collect-Components.ps1 -FromClipboard -Source "D:\Компоненты" -Target "D:\Собрано"

# список из файла (по имени на строку), сначала пробный запуск — ничего не копируется
.\Collect-Components.ps1 -List .\список.txt -Source "D:\Компоненты" -Target "D:\Собрано" -DryRun
```

Если скрипт не запускается из-за политики выполнения: `powershell -ExecutionPolicy Bypass -File .\Collect-Components.ps1 …`.

## Как работает

- Поиск — по имени файла во всей папке компонентов (с подпапками, без `OldVersions`).
- У найденных сборок, чертежей и производных деталей зависимости читаются через Apprentice
  (нужен Inventor или бесплатный Inventor View) — на всех уровнях. Зависимости тоже ищутся **только
  в папке компонентов**, по имени (старые пути из сборок не используются); не нашлась — в отчёте
  с путём, по которому её ждала сборка. В окне видно, сколько зависимостей у каждой сборки.
  Без Apprentice собираются только файлы из списка (будет предупреждение). `-NoDependencies` — не собирать зависимости.
- Несколько файлов с одним именем — берётся самый новый, остальные перечислены в отчёте.
- В строке списка может быть путь или таблица (через табуляцию) — берётся имя файла из первого поля.
- Исходные файлы не меняются; у копий снимается «только чтение».
- Все файлы копируются в одну папку (без подпапок).
