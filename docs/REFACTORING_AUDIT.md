# Аудит и рефакторинг основных подсистем

Исходное состояние: коммит `096044e`. Проверены ядро, настройки и загрузка модулей,
индекс и карточки проекта, хранение/импорт/изменение компонентов, резервные копии,
операции с файлами и протокол связи Explorer ⇄ Inventor. Исправления ниже относятся
к подтверждённым дефектам; это не утверждение об отсутствии остальных ошибок.

## Исправления и разделение ответственности

| Область | Проблема | Итог |
|---|---|---|
| Пути библиотеки | `GetFullPath` принимал абсолютные пути, `..`, альтернативные потоки Windows; обратный слеш не нормализовался на Linux | Общий `ContainedPath` проверяет относительные пути, сегменты, устройства Windows и границу корня. Его используют библиотека, архивы и имена настроек |
| Генерация имён | Расширение могло содержать фрагмент пути; не учитывались COM¹/LPT¹ и CONIN$/CONOUT$ | Проверка расширений и очистка специальных имён до записи |
| Настройки | Разные экземпляры использовали один `.tmp`, мешая параллельному сохранению | Общий `AtomicFile`: уникальный соседний файл, замена после записи, очистка своего временного файла. Сериализация выполняется до записи |
| Конфигурация модулей | `Modules: null`, пустые элементы и повторяющиеся Id приводили к исключениям или неоднозначности | Проверка формата, безопасное включение модулей по умолчанию и диагностическое сообщение |
| Сессия проекта | Проект и дерево менялись до успешного построения индекса; событие могло получить Root другого открытия | Сначала строится полный снимок состояния, затем публикуется одной заменой; событие получает локальное дерево своей операции |
| Обход дерева | Рекурсивный обход мог переполнить стек | Итеративный обход документов и каталогов анализатора |
| Карточки | Десериализация не проверяла null-коллекции, неизвестные уровни замечаний и несогласованные счётчики | Отдельный `ProjectHealthCardStore` отвечает за формат, проверку и атомарное сохранение; анализ не занимается файловым форматом |
| Миграции | Configure во время миграции мог пометить новую БД как уже обновлённую | Снимок конфигурации и сравнение перед фиксацией признака миграции; новая конфигурация мигрируется отдельно |
| Отмена БД | Проверка подключения превращала отмену в обычное сообщение об ошибке | OperationCanceledException передаётся вызывающему коду |
| Удаление компонента | Запись удалялась до файловой операции; заблокированный файл оставлял БД и диск в разных состояниях | Файл временно перемещается до фиксации БД, при ошибке возвращается. Ошибка последующей очистки записывается в журнал |
| Архивы | Циклические разделы вызывали бесконечную рекурсию; повреждённая структура проверялась слишком поздно | Итеративный порядок разделов, проверка родителей и циклов, таблиц, путей и дублирующихся файлов до обращения к БД |
| Контрольные суммы | Добавленный в ZIP файл без записи в Checksums мог не проверяться | Такой архив считается повреждённым, восстановление не начинается |
| Параллельные операции | Создание копий могло использовать общий `.part`; имена временных папок восстановления и журналов зависели только от времени | Уникальные временные файлы/папки и GUID в имени итогового ZIP. Регрессионный тест выявил коллизию при подходе «проверить свободное имя, затем переименовать»; этот подход удалён |
| Каналы связи | Повторный Dispose, параллельное подключение, исключения подписчиков и недопустимые таймауты нарушали жизненный цикл | Идемпотентное завершение, последовательное подключение, отмена подключения при Dispose, изоляция подписчиков, проверка таймаута до отправки запроса |

Схема БД и миграции не менялись. Поддерживаемый формат карточки остался версии 1;
повреждённые карточки требуют повторного анализа. Архивы с недопустимыми путями,
циклами, несовместимым форматом или отсутствующими контрольными суммами отклоняются.

## Проверка

.NET SDK 8.0.427, Debian Linux, PostgreSQL 17.11. Количества ниже — исполненные
тестовые случаи xUnit, включая строки параметризованных тестов.

| Набор | До | После | Добавлено |
|---|---:|---:|---:|
| Core.Tests | 294 | 376 | 82 |
| Library.Tests | 453 | 537 | 84 |
| Всего | 747 | 913 | 166 |

Пропусков и ошибок нет. Интеграционные тесты выполнялись с `PDMLITE_TEST_PG`,
а не пропускались. Рост — примерно 22%; измерение покрытия строк не выполнялось.

Новые сценарии включают:

- параллельные записи настроек, ошибку сериализации, отмену и неудачную замену файла;
- пути Windows и Linux, выход из корня, альтернативные потоки, имена устройств;
- повреждённые настройки и карточки, null-поля и неизвестные уровни замечаний;
- деревья и иерархии разделов глубиной 20 000 без рекурсии;
- отменённое/неуспешное открытие проекта без изменения предыдущей сессии;
- обрыв связи, ошибку подписчика, повторное завершение, параллельное подключение,
  неправильные таймауты без запуска обработчика и запрос после отмены;
- смену БД во время настоящей миграции, заблокированной транзакцией PostgreSQL:
  тест ждёт подтверждённого ожидания блокировки через `pg_stat_activity`;
- отказ БД при удалении через тестовый триггер и отказ файловой системы до удаления;
- циклы, отсутствующих родителей, повреждённые таблицы, опасные и повторяющиеся
  пути ZIP, отсутствие контрольной суммы и одновременное создание копий.

Команды из корня репозитория:

```sh
dotnet test tests/PdmLite.Core.Tests -m:2
dotnet test tests/PdmLite.Library.Tests -m:2
```

Также без ошибок и предупреждений собраны все семь модулей, проект инструмента
миграций и отдельная проверочная сборка реальных окон/модели Explorer без Apprentice.

## Границы проверки и следующие этапы

Полная сборка AddIn/Explorer и запуск WPF не подтверждены: облачная Linux-среда
не содержит Autodesk.Inventor.Interop.dll и Inventor COM. Windows-ветвь теста
блокировки файла не выполнялась: на Linux проверялся отказ через права каталога.
Нужен прогон в Windows с Inventor 2025, включая подключение, вставку, переименование,
удаление занятого файла, восстановление архива и визуальную проверку карточки.

Проверка `ContainedPath` лексическая: это не разрешение физических junction/symlink.
Работа с библиотекой через такие перенаправления требует отдельной политики.
Атомарность замены одного файла не означает транзакцию между PostgreSQL и диском
при аварийном завершении процесса. Для такой гарантии нужен сохраняемый журнал
восстановления операций и тесты аварийного завершения. Архивирование одновременно
изменяемых в Inventor документов также требует отдельного сценария согласованного
снимка.

Крупные LibraryImportService, LibraryItemService и ProjectFileOperations сохраняют
свою предметную последовательность и существующие регрессионные тесты. Их дальнейшее
разделение на планирование, файловую транзакцию и фиксацию БД стоит выполнять по
отдельным операциям с проверкой в Inventor, а не механически переносить методы.
