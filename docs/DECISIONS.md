## Правила формирования имени файла

Правило: **`{Обозначение}{Код} {Наименование}.{расширение}`**.

| Документ | Пример |
|---|---|
| Сборка | `АБВГ.00.00.000СБ Жгут.iam` |
| Сборочный чертёж | `АБВГ.00.00.000СБ Жгут.dwg` |
| Электромонтажный чертёж | `АБВГ.00.00.000МЭ Жгут.dwg` |
| Деталь (без кода) | `АБВГ.00.00.001 Провод.ipt` |
| Исполнение | `АБВГ.00.00.000-01СБ Жгут.iam` |

- Обозначение и код документа по ГОСТ 2.102 (`СБ`, `МЭ`, `ВО`, `Э3`, `ПЭ3`…) пишутся **слитно**;
  наименование — **через пробел**, пробелы внутри наименования сохраняются (повторы схлопываются).
- Код — 1–3 заглавные русские буквы и до двух цифр сразу после обозначения; у каждого файла комплекта
  он свой и при переименовании сохраняется.
- Запрещённые в Windows символы `: * ? " < > |` удаляются, `/` и `\` заменяются на `-`; точка и пробел
  в конце имени убираются.
- Документы одной модели узнаются по обозначению: всё с тем же обозначением в той же папке (любой код,
  любое расширение, в том числе PDF) — один комплект. Имя не по правилу (например, `Кронштейн.ipt`) —
  комплект по одинаковому имени (`Кронштейн.idw`).
- iProperties при переименовании: «Обозначение» модели — обозначение без кода, чертежа — с кодом
  (`АБВГ.00.00.000СБ`); «Наименование» (Title) — наименование.
- Контроль длины полного пути: до 259 символов.

# Запланированные функции

1. **Общая стандартная библиотека — первая главная функция.** Требования и устройство —
   в [LIBRARY.md](LIBRARY.md). Сделаны шаги Б1 (база, хранилище, добавление, каталог с изменением
   и удалением), Б2 (утилита подготовки файлов), Б3 (панель библиотеки, вставка в сборку,
   подключение к проекту), Б4 (Content Center, проверка сборки) и Б6 (резервные копии).
2. **Обозначения по стандартам не проверяются на формат** — только коды латиницей и пробелы;
   стандарт можно указать вручную, если он распознан неверно.
