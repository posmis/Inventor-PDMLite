# Принятые решения

| # | Тема | Решение |
|---|---|---|
| 1 | Язык, платформа | C#, .NET 8, Inventor 2025 |
| 2 | Архитектура | Модульная: ядро, адаптеры, подключаемые модули, два хоста (AddIn, Explorer) |
| 3 | БД | PostgreSQL, сервер на ПК пользователя (пока один пользователь) |
| 4 | Пользователи | Учётные записи создаёт администратор; права в Explorer задаёт администратор |
| 5 | Имя файла | `{Обозначение}_{Наименование}`, пробелы в наименовании заменяются на `-` |
| 6 | iProperties | Поля выбираются так, чтобы основная надпись чертежа заполнялась корректно |
| 7 | Чертежи | У модели может быть несколько чертежей (сборочный, электромонтажный и т.п.) |
| 8 | Explorer | Работает через Apprentice (Inventor View установлен); 3D-просмотр не делаем |
| 9 | Сторонние PDM / iLogic | Vault не используется; iLogic-правил, зависящих от имён файлов, нет |
| 10 | Название | PdmLite |

## Правила формирования имени файла (предложение)

- Разделитель обозначения и наименования — `_`.
- Пробелы в наименовании → `-`, повторяющиеся пробелы схлопываются.
- Запрещённые в Windows символы `\ / : * ? " < > |` удаляются или заменяются.
- Источник истины — iProperties и БД, имя файла только генерируется (обратно не разбирается).
- Контроль длины полного пути (лимит Windows).

# Открытые вопросы

1. **Хранение файлов:** рабочая папка + индекс в БД (этап 1) или сразу хранилище с версиями
   и check-in / check-out.
2. **Формат чертежей:** `.idw` или `.dwg` (в обсуждении упомянут `.dwf` — уточнить).
3. **Имена нескольких чертежей одной модели:** код документа по ГОСТ 2.102
   (например, `АБВГ.301.001СБ_Рама-сварная.dwg`, `…МЭ_…`).
4. **Основная надпись:** нужен шаблон чертежа, чтобы определить, из каких iProperties
   заполняются графы.
5. **Установка PostgreSQL** на ПК пользователя: инсталлятор или Docker.
