# Стандартная библиотека PdmLite

Первая главная функция. Статус: **Б1, Б3 и Б4 реализованы** (база, хранилище, добавление, каталог; панель и вставка в сборку; отделение Content Center и проверка сборок).

Единая для всех проектов библиотека стандартных и покупных компонентов, отделённая от
Content Center Inventor и не привязанная к конкретному проекту.

## Требования

| Что | Решение |
|---|---|
| Состав | Всё: ГОСТ, ISO и прочие стандарты; покупные изделия (кабельные вводы, разъёмы и т.п.) разных производителей |
| Объём | Сотни — тысячи позиций |
| Модели | Каждый типоразмер — отдельная модель (`.ipt`, при необходимости `.iam`); без iPart/iAssembly |
| Обмен с другими САПР | Кнопка «Экспорт в CAD-формат»: пользователь выбирает формат (STEP, IGES и др.) |
| Хранение | Файлы — в папке библиотеки на ПК пользователя; сведения о компонентах — в PostgreSQL |
| Права | Чтение — все. Добавление — с допуском. Удаление — администратор или спецдопуск. Пока один пользователь — работает как администратор, учётные записи позже |
| Изменение компонента | Сборки остаются на старой версии, пока пользователь не обновит; перед обновлением — резервная копия сборки (вариант «Б») |
| Content Center | Полностью отделён: из него в библиотеку ничего не попадает, кроме файла, сохранённого отдельно и внесённого через «Добавить в библиотеку» |
| Обозначение стандартных изделий | Строго как в стандарте на компонент |
| Обозначение покупных изделий | `<Наименование> <тип/артикул> <производитель>` (ГОСТ 2.106, «Прочие изделия»), например «Кабельный ввод SKINTOP MS-M 20x1,5 Lapp» |
| Имя файла | Обозначение как есть, с пробелами; заменяются только запрещённые в Windows символы |
| Буквы в обозначениях | В кодах — латиница (`M`, `x`, `A`…); слова остаются русскими: «Болт M10-6gx25.109 ГОСТ 7798-70» |
| Раздел спецификации | Свойство `SPEC_Section` в файле (для системы спецификаций пользователя): стандартное → `StandardProducts`, покупное → `OtherProducts`. Если в добавляемом файле оно уже есть — тип берётся из него |
| Наведение порядка в существующих файлах | Нужна утилита (см. ниже) |
| Резервные копии | Выгрузка всей библиотеки в один архив и загрузка из него с полной заменой текущей; по расписанию — не нужны |
| Сборки в библиотеке | Да (`.iam`); все их детали тоже в библиотеке |

## Хранение

Inventor работает только с файлами на диске, поэтому модели хранятся в папке, а база данных
хранит всё остальное:

```
D:\PdmLite\Library\                       ← подключается во все проекты Inventor как библиотека «PdmLite»
  Крепёж\Болты\ГОСТ 7798-70\Болт М8-6gx20.58.016 ГОСТ 7798-70.ipt
  Электротехника\Кабельные вводы\Lapp\SKINTOP MS-M\...
  _versions\                              ← старые версии компонентов (ведёт только PdmLite)
```

PostgreSQL: каталог (классификатор), карточки компонентов (обозначение, стандарт, типоразмер,
производитель, артикул…), версии, контрольные суммы файлов, где используется (какие сборки
ссылаются на компонент), журнал изменений.

Папка меняется только через PdmLite; файлы помечены «только чтение». Пока один пользователь на
одном ПК, роли проверяются в интерфейсе PdmLite; защита на уровне файлов — при переезде на сервер.

Библиотека в проектах Inventor подключается как раздел «Библиотеки» `.ipj` с именем «PdmLite».
Сборки хранят ссылку «имя библиотеки + относительный путь», поэтому папку можно перенести
(на другой диск, позже — в сеть), поменяв только путь в проектах.

## Классификатор

Стандартные изделия — по стандарту, покупные — по производителю:

```
Крепёж ── Болты · Винты · Гайки · Шайбы · Шпильки · Шурупы и саморезы · Заклёпки · Штифты · Шплинты · Кольца стопорные
Подшипники ── Шариковые · Роликовые · Корпусные узлы
Детали машин ── Шпонки · Муфты · Звёздочки и шкивы · Пружины
Уплотнения ── Кольца · Манжеты · Сальники
Электротехника ── Кабельные вводы · Разъёмы · Клеммы · Кабель-каналы · Корпуса · Аппараты
Пневматика и гидравлика ── Фитинги · Цилиндры · Распределители
Прочие покупные
```

Стандартное изделие: Раздел → Группа → Стандарт → типоразмеры.
Покупное: Раздел → Группа → Производитель → Серия → артикулы.
Плюс общий поиск (обозначение, наименование, артикул), фильтры, «Избранное», «Недавние».

## Функции

1. **Добавить в библиотеку** (Inventor и Explorer), сразу много файлов или папка:
   анализ → обязательные проверки (свойства, формат обозначения, дубликаты по обозначению и
   содержимому, внешние ссылки, связь с Content Center, имя файла) → таблица результатов с
   исправлением ошибок → «Внести»: раскладка по классификатору и запись в базу.
   Раздел определяется по стандарту/ключевым словам; ручные исправления запоминаются.
2. **Каталог** в окне PdmLite (Inventor) и в Explorer: дерево, поиск, превью, свойства,
   «Вставить в сборку».
3. **Подключение к проектам**: проверка, что библиотека «PdmLite» есть в активном проекте Inventor.
4. **Отделение Content Center**: библиотеки Content Center в проектах отключаются; компонент
   Content Center в сборке — предупреждение и предложение заменить библиотечным аналогом.
5. **Проверка сборки**: найти стандартные компоненты не из библиотеки (копии в проекте,
   Content Center) → предложить замену → резервная копия → замена ссылок.
6. **Версии**: изменение компонента создаёт новую версию; сборки остаются на старой;
   «Обновить» — с резервной копией сборки.
7. **Экспорт в CAD-формат**: выбранные компоненты → STEP / IGES / … (через Inventor).
8. **Утилита наведения порядка** в существующих файлах — см. ниже.
9. **Резервная копия библиотеки**: выгрузка и загрузка — см. ниже.

## Утилита наведения порядка (Б2)

Задача — функционал, а не наполнение: правила задаёт пользователь, в код ничего не зашито.
**Формат обозначения по стандартам не проверяется**: у каждого ГОСТ свои исполнения, размеры
«под ключ» `(S18)`, классы прочности `.58`, `.109`, покрытия — обозначение берётся как есть,
меняется только запись кодов (латиница) и пробелы.

Всё — в окне «Добавить в библиотеку»:
- **Обозначение из ▾** — для выделенных строк взять обозначение из «Обозначения», «Описания»,
  «Наименования» или имени файла (по умолчанию — «Обозначение», если оно заполнено). Колонка
  **Источник** показывает, откуда оно взято; «Вручную» — исправлено в таблице.
- **Правка выделенных…** — тип, производитель, раздел для всех выделенных строк разом, и
  поиск/замена в обозначении (обычный текст или регулярное выражение, с предпросмотром).
- **Правила…** — правила замены, которые применяются ко всем файлам при анализе, по порядку
  (например, `Болт_` → `Болт `). Есть проверка на примере. После сохранения обозначения в списке
  готовятся заново; исправленные вручную не трогаются. Правила хранятся в базе.
- **Стандарт** в таблице можно исправить, если он распознан неверно (пустое значение — снова
  распознавать из обозначения). То же — в карточке каталога: флажок «вручную».
- **Сохранить список… / Открыть список…** — файл `.pdmlist` с правками (обозначения, источник,
  тип, стандарт, производитель, раздел, исключённые), чтобы разобрать большую папку в несколько
  приёмов. При открытии файлы анализируются заново, пропавшие — в «Пропущенных».

Как и раньше: пропуск `OldVersions`, сравнение имени файла с iProperties, поиск дубликатов
(по обозначению и содержимому), снятие метки Content Center, предпросмотр пути в библиотеке.

## Резервные копии библиотеки

**Выгрузить** — один архив `.zip`, в котором всё, чтобы восстановить библиотеку на этом или
другом компьютере:
- файлы библиотеки, включая старые версии (`_versions`);
- данные из базы (классификатор, карточки, версии, журнал) — в формате PdmLite (JSON),
  не зависящем от версии PostgreSQL;
- описание архива: дата, версия PdmLite, число компонентов, контрольные суммы файлов.

**Загрузить** — **полная замена** текущей библиотеки: проверка архива (целостность,
контрольные суммы, версия) → предпросмотр (что изменится) → перед загрузкой автоматически
делается резервная копия текущей библиотеки → восстановление файлов и данных.

Автоматических копий по расписанию нет — выгрузка только по команде пользователя.

Связи «где используется» (какие сборки ссылаются на компонент) относятся к проектам, а не к
библиотеке: после загрузки они пересчитываются сканированием проектов.

## Как пользоваться (Б1)

1. Установить PostgreSQL и создать базу: `powershell -ExecutionPolicy Bypass -File deploy\install-postgres.ps1`.
2. PdmLite Explorer → «Настройки библиотеки…»: проверить подключение, выбрать папку библиотеки
   (по умолчанию `Документы\PdmLite\Library`).
3. «Добавить в библиотеку…» → «Добавить файлы…» или «Добавить папку…» → в таблице поправить
   обозначение, тип, производителя, раздел → «Внести в библиотеку».

Таблицы базы создаются автоматически при первом подключении. Свойства файлов читаются и
записываются через Apprentice (нужен Inventor или Inventor View), Inventor запускать не нужно.

### Проверки при добавлении

| Ошибка (не внесётся) | Замечание (внесётся) |
|---|---|
| нет доступа к свойствам / файл не читается | свойства файла расходятся с обозначением |
| нет обозначения | файл из Content Center |
| у стандартного изделия не найден стандарт | у покупного не указан производитель |
| не выбран раздел или выбран раздел, а не группа | |
| дубликат: в библиотеке или в списке — по обозначению или содержимому файла | |
| компоненты сборки не в библиотеке и не в списке | |
| слишком длинный путь или файл уже лежит в папке библиотеки | |

Справочно (не влияет): обозначение приведено к единому виду, имя файла будет изменено.

Пропускаются: резервные копии Inventor (`OldVersions`), не детали и не сборки, файлы, уже лежащие
в папке библиотеки.

### Что делает «Внести»

Для каждого компонента отдельно (ошибка одного не отменяет остальные): копирование в папку
библиотеки → для сборки — перевод ссылок на файлы библиотеки → запись свойств (Обозначение,
Описание, Наименование = обозначение; пользовательские: `SPEC_Section`, «Стандарт», «Производитель»,
«Раздел библиотеки», «PdmLite.LibraryId») → «только чтение» → запись в базу (компонент,
версия 1, состав сборки, журнал). Исправленный вручную раздел запоминается для следующих
компонентов того же стандарта (или с тем же началом обозначения). Исходные файлы не меняются.

### Каталог: изменение и удаление

PdmLite Explorer → «Каталог библиотеки…»: список внесённых компонентов, поиск, фильтр по разделу.

- **Изменить…** (или двойной щелчок): обозначение, тип, стандарт (если распознан неверно —
  флажок «вручную»), производитель, раздел. Смена типа меняет `SPEC_Section` в файле. Проверки — те же, что
  при добавлении. При сохранении файл переименовывается и при необходимости переносится, свойства в
  нём перезаписываются, сборки библиотеки, в которые входит компонент, перевязываются на новый файл,
  в журнал пишется «было → стало». При ошибке всё возвращается как было.
- **Удалить**: файл и запись в базе; нельзя, пока компонент входит в сборку библиотеки.
- Сборки **проектов**, куда компонент уже вставлен, сами не переписываются, но при открытии такой
  сборки в Inventor плагин находит компонент по новому пути (см. ниже) — останется сохранить сборку.

### Добавление в библиотеку прямо из сборки (Inventor)

Выделите в сборке (в браузере или на экране) детали или подсборки → лента PdmLite →
**«Добавить в библиотеку»**:
1. несохранённые выделенные документы предлагается сохранить (в библиотеку копируется файл с диска);
2. открывается то же окно «Добавить в библиотеку» со всеми проверками и утилитой подготовки;
   для подсборки в список сразу попадают все её компоненты; уже внесённые (тот же файл)
   исключаются, и их можно сразу заменить в сборке;
3. после «Внести» выделенные компоненты в активной сборке (и в её подсборках) заменяются
   компонентами библиотеки; копии изменяемых сборок — в `%LOCALAPPDATA%\PdmLite\backups`.
   Сохраняет сборку пользователь.

Внутри Inventor свойства файлов читаются и пишутся через Inventor API (копия в библиотеке
открывается невидимо, сохраняется и закрывается), в Explorer — через Apprentice.

### Ненайденные компоненты библиотеки при открытии сборки

Если сборка ссылается на компонент библиотеки, которого нет по старому пути (изменили обозначение,
стандарт или раздел; перенесли папку библиотеки), плагин подставляет текущий файл — окно Inventor
«Файл не найден» для него не появляется. Как ищется:
1. по старому пути компонента из журнала изменений библиотеки;
2. по тому же пути внутри библиотеки, если папка библиотеки теперь другая;
3. если файла точно нет — по имени файла или обозначению (только при единственном совпадении).

В строке состояния Inventor появляется сообщение, подмена записывается в журнал PdmLite.
Сохраните сборку — ссылка запишется новая. Файлы проекта (не библиотеки) не затрагиваются.

### Обслуживание

Каталог → «Обслуживание…». Каждая операция: поиск (только чтение) → таблица изменений с
отметками → окно подтверждения со **всем списком изменений** (по умолчанию выбрана «Отмена») → запись.

**Свойства в файлах** — например, записать `SPEC_Section` в компоненты, внесённые до его
появления, или снять оставшиеся метки Content Center. Охват: выделенные в каталоге или вся библиотека.
1. **Проверить** — только чтение. Таблица: по строке на каждое изменение — свойство, «сейчас в
   файле» (красным), «будет записано» (зелёным); строки сгруппированы по файлам, у файла — отметка.
2. **Применить к отмеченным файлам…** — окно со списком всех изменений и итогом по свойствам
   («SPEC_Section — в 12 файлах»), затем запись.

**Дубликаты** — один и тот же компонент, внесённый дважды:
- признаки: одинаковый файл; обозначения, которые отличаются только пробелами, знаками или регистром;
- в каждой группе выбирается, какой компонент оставить (по умолчанию — стоящий в сборках библиотеки,
  иначе самый ранний); группу можно не объединять;
- **Объединить отмеченные группы…** — окно со списком: что удаляется и чем заменяется; затем лишние
  компоненты удаляются (файл и запись), сборки библиотеки перевязываются на оставленный;
- сборки проектов не меняются: при открытии в Inventor ссылка на удалённый файл подменяется
  оставленным компонентом (сохраните сборку).

### Дублировать компонент

Каталог → выделить компонент → **«Дублировать…»**: копия того же файла (те же размеры) с другим
обозначением — например, другое покрытие или класс прочности. Окно — как «Изменить…»: тип, стандарт,
производитель, раздел; обозначение копии должно отличаться. В копию записываются свои свойства,
в журнале — «скопирован из …».

Защита при записи свойств:

Защита для большой библиотеки:
- перед записью каждый файл проверяется заново; если он уже в порядке, не изменяется;
- перед записью — резервная копия файла, при ошибке файл восстанавливается, остальные продолжаются;
- база (контрольная сумма) обновляется после каждого файла; остановить можно в любой момент;
- итог и ошибки — в окне, запись в журнале библиотеки.

### Панель «Библиотека» и вставка в сборку (Б3)

Вкладка «Библиотека» рядом с деревом проекта — в окне PdmLite в Inventor и в Explorer:

- дерево: раздел → группа → стандарт (или производитель) → компоненты, с числом компонентов;
- поиск по обозначению без учёта похожих букв и пробелов: «м8» найдёт «M8», «2х4» — «2x4»;
- **Вставить в сборку** (или двойной щелчок): в Inventor запускается штатная команда «Вставить
  компонент» с выбранным файлом — место указывается щелчком, можно вставить несколько экземпляров.
  Из Explorer команда уходит в запущенный Inventor; активным документом должна быть сборка;
- «Открыть», «Показать файл».

**Подключение к проекту.** В Inventor панель проверяет, есть ли в активном проекте (.ipj, раздел
«Библиотеки») библиотека «PdmLite» с папкой библиотеки. Если нет или папка другая — жёлтая
плашка с кнопкой «Подключить к проекту». Inventor меняет проект только при закрытых документах.

Каталог обновляется после добавления и изменения в Explorer (в этом же приложении) и по кнопке
«Обновить».

### Отделение Content Center и проверка сборки (Б4)

**Вставка из Content Center.** Плагин следит за вставкой компонентов. Если вставлен компонент
Content Center, PdmLite предупреждает:
- в библиотеке есть такой же (по обозначению) — предлагает заменить им все вхождения в этой сборке;
- такого нет — советует добавить его в библиотеку.

Каждый файл в каждой сборке — один раз за сеанс Inventor. Компоненты из папки библиотеки не
проверяются. При внесении в библиотеку метка Content Center в файле снимается (компонент
становится самостоятельной деталью); у ранее внесённых её снимает «Обслуживание». Отключить предупреждения:
`WarnOnContentCenter: false` в `%AppData%\PdmLite\library.json`.

**Проверить сборку** (кнопка на вкладке PdmLite в Inventor) — по всей активной сборке, включая
подсборки:

| Замечание | Что значит | Замена |
|---|---|---|
| Content Center | компонент из Content Center | если в библиотеке есть такое же обозначение |
| Копия | копия библиотечного компонента вне библиотеки (например, в папке проекта) | библиотечным |
| Нет в библиотеке | стандартное изделие (в обозначении есть стандарт), которого нет в библиотеке | — добавить в библиотеку |

Сопоставление — по обозначению (Part Number, иначе имя файла) без учёта похожих букв,
пробелов и регистра. Собственные детали проекта не проверяются.

«Заменить отмеченные»: замена делается в той сборке, где компонент стоит непосредственно
(сборка и подсборки), все вхождения сразу. Перед заменой изменяемые сборки копируются в
`%LOCALAPPDATA%\PdmLite\backups\<дата>_<сборка>`. Сохраняет сборки пользователь. Сборки
только для чтения (библиотечные) не изменяются — об этом сообщается.

Библиотеки Content Center в проекте Inventor PdmLite пока не отключает. Чтобы закрыть Content
Center полностью: Inventor → Проекты → активный проект → «Настроить библиотеки Content Center» →
снять все библиотеки.
