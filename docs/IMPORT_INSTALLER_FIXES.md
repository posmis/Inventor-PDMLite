# Проверка импорта и обновления установщика

## Поведение

1. Импорт сборки подтверждается повторным чтением ссылок после последней записи свойств. Сравнивается полный набор ожидаемых библиотечных путей, проверяется наличие файлов. При несовпадении или ошибке чтения копия удаляется, запись компонента, его версии, связей и журнала не фиксируется. Исходники не изменяются.
2. Очередь импорта строится по графу зависимостей за O(компоненты + ссылки). Вложенные и общие подсборки вносятся раньше родителей независимо от порядка входного списка. Циклы и зависимые от циклов сборки получают явную ошибку до копирования. Независимые компоненты продолжают импортироваться.
3. Новый EXE-установщик не передаёт административный пароль ни через `-Password`, ни через `--superpassword`. Создаётся защищённый Windows named pipe, доступный инициатору и администраторам. Перед отправкой проверяется PID подключившегося процесса. Повышенный PowerShell пишет пароль в приватный файл параметров EDB, задав ACL администраторам и SYSTEM до записи. Срабатывание UAC под другой учётной записью не требует расшифровки DPAPI исходного пользователя. Файл параметров удаляется при успехе и при исключении. Внезапное завершение процесса/ОС может оставить приватный временный файл; доступ к нему остаётся ограниченным ACL.
4. Inno перед установкой резервирует три программные папки целиком. Новая версия устанавливается в пустые папки, поэтому устаревшие модули и зависимости не подхватываются загрузчиком. При ошибке восстанавливаются прежние папки. Журнал пишется атомарно; ошибки восстановления не уничтожают резервные файлы. После успешной настройки сбой очистки не вызывает откат. Настройки, библиотека и PostgreSQL вне этих папок не перемещаются. Данные библиотеки внутри программных папок блокируют обновление. При удалении старых файлов junction/symlink не обходятся.

## Тесты

- `ImportIntegrityTests`: отсутствие замены, частичная замена, потеря замены при сохранении свойств, ошибка повторного чтения; вложенность из нескольких уровней с общей подсборкой; цикл и зависимая сборка при независимой детали. Тесты работают с файлами и настоящим PostgreSQL, проверяют БД и сохранность исходников.
- `PostgresSecretChannelTests` (Windows): передача правильному PID; отказ другому процессу без раскрытия пароля; завершение клиента до подключения; отмена ожидания.
- `deploy/installer/test-postgresql-options.ps1` (Windows PowerShell): действительные NTFS ACL, отсутствие пароля в аргументах дочернего процесса, удаление файла после успеха/ошибки; отказ неверному hash и неверному формату секрета. Запуск EDB заменён проверяющей заглушкой, сам сервер тестом не устанавливается.
- `deploy/installer/test-update.ps1`: обновление без старых модулей; полный и частичный откат; откат первой установки; защита границ транзакции; защита библиотеки; очистка junction/symlink; реальный отказ во втором переносе через заглушку операции; сохранение копий при заблокированном откате; повторный откат; сохранение новой версии при отказе очистки.
- Windows CI дополнительно компилирует оба рецепта Inno Setup с фиктивной полезной нагрузкой.

Проверки на Linux не подтверждают работу NTFS ACL, UAC, Windows named pipes, реального EDB или Apprentice COM. Для полного приёмочного теста требуются Windows, Inventor 2025 и реальные CAD-файлы: проверить импорт вложенной сборки, затем убрать исходную папку и открыть библиотечную сборку. Проверить установку с UAC от обычного пользователя, установку под другой административной учётной записью и обновление с удалённым модулем.
