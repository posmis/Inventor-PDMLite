## Дополнительная очистка

- Подписки Inventor подключаются отдельным Attach после регистрации владельца. Синхронизация активного проекта имеет отмену и отслеживаемые задачи. Поздние COM-события после остановки игнорируются.
- Модуль библиотеки отменяет отложенное резервное копирование и ожидает его в ShutdownAsync. Ошибка одного шага очистки не пропускает остальные шаги или ожидание задачи.
- PdmHost ожидает асинхронную остановку модулей, их областей событий и контейнера; logger освобождается последним. Повторный Start/Dispose не дублирует операции.
- IPdmModule получил ShutdownAsync с реализацией по умолчанию через существующий Shutdown. ConfigureServices предназначен для регистраций: запуск ресурсов нужно откладывать до Initialize/фабрик контейнера, а не выполнять побочные действия при регистрации.

## Границы проверок

Тесты используют настоящие файлы, очереди, потоки, named pipes и PostgreSQL. На Linux STA-helper выполняется как обычный рабочий поток для проверки очереди; Windows CI дополнительно использует настоящий STA. Полная активация, UI и COM-события требуют приёмки на Windows с Inventor 2025.

Нельзя безопасно принудительно прервать зависший COM-вызов внутри процесса. При таймауте вызывающие задачи уже завершены, но завершающийся STA и его ресурсы остаются до возврата native-вызова. Для жёсткого завершения нужен отдельный процесс; служебный ApprenticeHost уже использует процессную изоляцию.

После исключения CommitAsync отсутствие строки в одном контрольном чтении не доказывает откат неизвестного исхода COMMIT. Поэтому сомнительная копия сохраняется с явным сообщением для проверки, вместо риска удалить файл уже зафиксированного компонента. До начала фиксации отмена очищает незарегистрированную копию штатно.

Журнал настроек обеспечивает восстановление согласованной пары для участвующих читателей/писателей JsonSettings и редактора. Он не является транзакцией PostgreSQL и не переносит уже начатые файловые/БД-операции в другое подключение.
