# Карточка состояния проекта

В PdmLite Explorer откройте папку проекта или `.ipj`. В группе **Проект**:

- **Анализ проекта…** — запускает полный анализ и открывает карточку.
- **Карточка проекта…** — открывает последний сохранённый результат; если его ещё нет,
  предлагает выполнить анализ.

В окне можно повторить анализ, остановить его, скопировать замечания или перейти к
выбранному документу в проводнике. Прогресс показывает текущий документ. Карточка
содержит дату, количество деталей, сборок, чертежей и презентаций, число прочитанных
документов, ошибок и замечаний. Ошибки чтения остаются видны: такой проект не получает
статус «Проверки пройдены». Пустой проект также отмечается замечанием.

## Просмотр результатов

- Слева — виды проверок с количеством замечаний. Выбор ограничивает список.
- Над списком — фильтры «Все», «Ошибки», «Замечания» со счётчиками.
- Поиск работает по имени, полному пути и исходному сообщению, в том числе скрытому
  в краткой строке. `Ctrl+F` переводит фокус в поиск, `Esc` очищает его.
- В списке показаны имя и относительная папка документа. Очень длинное имя сокращено
  посередине с сохранением начала и расширения; полный путь доступен в подсказке.
  Длинные пути других файлов заменены кратким описанием проблемы.
- Внизу — подробности выбранной строки: полный путь и исходный текст без сокращений.
  Их можно выделить и скопировать. Размеры областей изменяются разделителями.
- «Показать файл» и двойной щелчок по строке показывают существующий документ
  в проводнике. Можно скопировать отдельно путь, замечание или весь текущий
  отфильтрованный список. Копирование сохраняет полные пути и сообщения.
- Дата сохранения видна внизу; путь к JSON — в подсказке. Описание границ анализа
  находится в сворачиваемом разделе «Что проверяет анализатор».

Организация использует приёмы диагностических окон
[Visual Studio Error List](https://learn.microsoft.com/en-us/visualstudio/ide/error-list-window)
и [VS Code Problems](https://code.visualstudio.com/docs/editing/editingevolved#_errors-warnings):
счётчики, фильтры, поиск и переход от списка к подробностям.

## Проверки

| Проверка | Результат |
|---|---|
| Не удалось прочитать свойства или ссылки документа | Ошибка с сообщением чтения |
| Ссылка на отсутствующий файл | Ошибка с исходным путём |
| Отсутствующая ссылка найдена в папках поиска или библиотеке PdmLite | Замечание с найденным путём; документы не изменяются |
| Файлы в разных папках имеют одинаковое имя | Замечание со списком файлов |
| Модели одного типа имеют одинаковое непустое обозначение | Замечание; совпадение обозначения модели и её чертежа разрешено |
| Не заполнены Part Number или Title | Замечание |
| В документе осталась метка Content Center | Замечание |

Анализ перечитывает свойства **всех** документов проекта, а не только изменившихся в
индексе. PostgreSQL для формирования и открытия карточки не требуется. Для чтения
реальных CAD-документов нужен установленный Inventor / Apprentice; поиск перемещённых
компонентов библиотеки использует существующий механизм PdmLite и его настройки.

## Сохранение и актуальность

Последняя карточка хранится в `%AppData%\PdmLite\ProjectHealth` в JSON. Она доступна
этому пользователю на этой машине после перезапуска Explorer. Идентификатор учитывает
полный путь папки и выбранного `.ipj`: разные проекты не перезаписывают карточки друг
друга. Это одна актуальная карточка на проект, без истории версий.

При открытии проверяются состав и SHA-256 содержимого документов проекта и файлов
`.ipj`; для внешних ссылок — наличие, размер и время изменения. Поэтому открытие
карточки большого проекта тоже может занять время, но не перечитывает свойства через
Apprentice. Изменённая карточка помечается устаревшей: для обновления нужно явно
запустить анализ. Если актуальность проверить не удалось, окно сообщает об этом.
После успешного анализа JSON заменяется атомарно; отмена и сбой сохраняют предыдущий
результат. Изменение файлов во время анализа требует повторной проверки.

Анализируется сохранённое состояние `.ipt`, `.iam`, `.idw`, `.dwg`, `.ipn` в папке
проекта. Исключены `OldVersions`, скрытые и системные папки/файлы, символические ссылки.
Недоступная обычная папка прерывает анализ, а не молча исключается. Несохранённые
изменения открытых документов, геометрическая корректность, коллизии и открываемость
моделей в Inventor не проверяются. Внешние модели проверяются как ссылки, без
рекурсивного чтения их состава. Изменение настроек папок поиска или каталога библиотеки
также является поводом явно повторить анализ.
