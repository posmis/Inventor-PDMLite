# Совместимость связи, уведомления Content Center и удаление

## Изменения

- При подключении Explorer к Inventor, передаче аргументов второму Explorer и команде плагина «Показать в Explorer» выполняется общий handshake: проверяются приложение, наличие ответа и точное совпадение версии протокола. Разные версии приложения с одинаковым протоколом разрешены. Неизвестный ping и некорректный ответ считаются ошибкой совместимости. До успешной проверки команды не отправляются.
- Ошибка совместимости передаётся в строку состояния Explorer с подсказкой об обновлении. Повторные одинаковые ошибки не публикуются бесконечно. После обновления плагина штатное переподключение восстанавливается. Второй Explorer при несовместимости не переходит к запуску нового экземпляра: исключение доходит до обработчика ошибки запуска.
- Новые запросы явно объявляют `protocolVersion`. Сервер отклоняет несовместимые запросы до вызова обработчика. Отсутствующее поле означает исходный протокол v1 — это сохраняет совместимость с существующими клиентами текущей версии, но не позволит принять их автоматически за будущую v2. Дополнительное поле не требует менять текущую версию протокола: старые v1-серверы игнорируют неизвестные JSON-поля.
- Обработчик вставки Content Center сохраняет `kEventNotHandled`. Получение COM-данных и публикация необязательного уведомления выполняются через защищённую границу. Недоступные обязательные пути приводят к пропуску уведомления и диагностике; сбой чтения обозначения оставляет его пустым, не мешая предупреждению. Отказ чтения не прерывает событие вставки.
- `deploy/uninstall.ps1` проверяет Inventor и Explorer до удаления. Уже отсутствующие файлы допускаются; отказы доступа и оставшиеся файлы приводят к ошибке с указанием пути и коду завершения 1. Регистрация плагина удаляется после удаления программных папок. Сообщение об успехе выводится только после полного выполнения. Скрипт предназначен для ручной установки `deploy/install.ps1`: EXE-установка направляет пользователя к штатному деинсталлятору Inno, чтобы не оставлять некорректную запись установленного приложения. Библиотека, база и настройки сохраняются.

## Проверки

- `LinkCompatibilityTests`: совпадающие/разные версии протокола, неправильное приложение, пустой/неполный/некорректный ответ, неподдерживаемый ping; отказ передачи команды несовместимому Explorer, handshake перед открытием проекта/выделением документа; отсутствие GetStatus и команд при несовместимости Inventor и восстановление после обновления; серверная проверка версии перед выполнением запроса, включая старый формат v1. Тесты используют реальные именованные каналы.
- `ContentCenterNotificationTests`: отказы классификации, получения путей, чтения определения документа и публикации; пустые обязательные пути; отсутствие лишних COM-вызовов для обычной детали; корректное событие. COM-ошибки моделируются делегатами, сами Autodesk COM-типы не подменяются.
- `deploy/installer/test-uninstall.ps1`: запущенные Inventor/Explorer, отказ удаления, оставшиеся после удаления файлы, успешное/повторное удаление, сохранность пользовательских данных и отказ ручного удаления EXE-установки. Скрипт выполняется также в Windows CI.

Реальная загрузка плагина и COM-событие Inventor требуют проверки на Windows с Inventor 2025. Linux-проверка делегатов подтверждает обработку исключений, но не заменяет эту проверку.
